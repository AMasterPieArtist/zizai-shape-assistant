# 自在身材：选餐交互更新 V3

更新日期：2026-10-11。应用版本 0.2.0，Prompt 1.4-optional-snack，规则 prototype-v1.1-optional。食品知识库仍为 food-catalog-v2.0-20261011，本次没有新增食品数据。

## 可以在哪里体验

### 1. 午餐推荐 → 搜索餐食或食材

输入“鸡肉”“米粉”“豆腐”等关键词，点击“搜索”。名称、食材及餐食类型均参与匹配；多个空格分开的词需要同时匹配。仍保留当前画像的忌口限制。

留空点击搜索，可浏览当前食品库中全部符合条件的搭配。结果多时可翻页；没有找到时提示更换关键词，不改动当前已选餐食。点击“选择这个”才采纳并保存到当天计划。支持搜索当前三张推荐卡片之外的方案。

点击“返回推荐”回到原有候选。早餐、晚餐与启用的下午茶也可搜索选择；已完成餐次先取消完成标记才可修改。

### 2. 午餐推荐 → 选择外卖

午餐或晚餐上方的“选择外卖”进入独立外卖页面。可切换午餐/晚餐外卖，搜索、筛选类型或点击“没有合适的，换一批”“不喜欢，换一批”。本次浏览不会改变画像中保存的食堂/外卖/自制偏好。

换批只浏览候选，采纳才修改正式计划。本次页面会话内换批排除已经看过的候选；看完会明确提示。刷新页面会重新开始浏览，已采纳的正式餐食保持保存。

外卖内容是已有食品库的常见点餐示例和品牌标准产品配餐，没有连接真实外卖平台、附近门店、实时菜单、价格、库存、配送或下单。部分品牌配餐含自备配菜，会在卡片明确标注，不能视作商家出售的完整套餐。

### 3. 今日计划 → 下午茶（可选）

点击“取消下午茶”，显示“今天不安排下午茶”，从当天计划的能量及其他营养合计中移除。原方案保留，点击“恢复下午茶”会恢复该方案并重新计入。三餐、已添加的饮品小食与运动不会因此删除或自动补偿。

已标记完成的下午茶不能直接取消安排，需先“取消完成”。下午茶取消时不能选餐、换批或标记完成，需先恢复。

取消后的统计采用实际启用餐次。如果低于原型参考规则，会如实显示未达项，不显示成全部通过。每日生成/替换仍验证保留的完整参考搭配，以避免用“可选”绕过原有生成护栏；这不代表取消后的三餐已满足全部营养需求。原型规则的数值阈值未改动，仍待专业复核。

额外添加的饮品与小食单独累计，取消下午茶不会自动取消这些条目。AI 动态调整接收 enabled 状态，程序禁止模型替换或自动恢复已取消的下午茶。演示奶茶模板在下午茶取消时会引导主动添加饮品，不改动正餐。

重新生成整个日期的计划会恢复下午茶，并重置餐食、小食和运动；确认框已明确说明。

## 保存与兼容

- 沿用 SQLite 计划 JSON，无需重建数据库或导入数据。旧计划缺少 enabled 字段时按启用处理。
- 搜索、翻页、外卖浏览不修改计划版本；采纳、取消/恢复才保存并递增版本。
- 保存沿用计划版本、画像版本、完成状态与旧草案失效机制。服务端重新查找合法候选，不能由网页提交任意菜名或热量绕过限制。
- API Key、个人画像、计划及历史不会因代码更新被覆盖。本次不主动调用付费模型。

## 运行

关闭原 Python 服务后，在 VS Code 终端运行：

```powershell
python "D:\github\自在身材\app.py" --port 8766
```

浏览器访问 `http://127.0.0.1:8766` 并刷新。无需重新填写 Key、删除数据库或重新生成当天计划。`/api/status` 的应用 version 应为 0.2.0；已有计划中的 Prompt 版本保留其生成时记录，新生成或新 AI 调整使用 1.4-optional-snack。
