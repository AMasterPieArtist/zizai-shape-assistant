# 食品数据接入说明 · 2026-10-10（历史版本）

当前版本见[餐食库扩充说明 V2](餐食库扩充说明_V2.md)，本页保留第一次升级的记录。

本次将下载的数据接入本地单用户 MVP，不需要安装新的数据库服务。

## 数据放在哪里

- `data/reference/dataset-v1.json`：程序使用的参考数据原文件，版本 zizai-food-reference-v1.1。
- `data/reference/source_evidence/`：官方条目抽取、品牌营养页摘录与新增熟牛肉条目的证据。
- `data/zizai.sqlite3`：实际运行数据库。`foods` 保存基础食品，`reference_products` 保存品牌规格，`recipe_templates` 保存示例配方，`catalog_meta` 保存版本与指纹。
- 原有 `profiles`、`plans`、`adjustments`、`events` 继续保存个人数据，不另建一套个人数据库。
- 下载的 Excel 用于人工查看与整理；直接修改 Excel 不会同步到应用。

## 当前覆盖

64 条基础食品；41 条品牌规格记录，其中 40 条可用于选择；19 组示例配方，包括15组餐食/加餐与4组自配饮品。原有菜谱顺序及ID保留，午餐/晚餐各增加8组候选；早餐增加5组，加餐增加2组。

「饮品与小食」现在有58项可选内容：6项原型条目、40项官方品牌规格、4项自配饮品、8项通用甜点零食，支持搜索与分类。资料充分的条目加入今日后，其参考热量会加到首页概览，刷新与重启后保留。奶茶等配方不明的旧条目仍显示待补充。

品牌数据按中国内地官方所列规格与标准配方使用，kcal由kJ÷4.184换算。没有公布的糖、咖啡因等保持null，不按零计算。不可把中杯自动换成每100ml，也不可用于改变糖奶和加料后的饮品。

Hot-Caramel-Macchiato-2 的中杯数据与卡布奇诺中杯的六项数值完全相同，保留原文并标记 hold_for_review；不能添加到计划，待品牌核验后再开放。配料与完整过敏原未知的产品，遇到任何忌口均暂停自动采纳。

自配红茶牛奶与拿铁是作者设计的固定克重示例，不是品牌奶茶配方。甜点零食使用USDA通用参考，页面明确标注非具体品牌。示例份量不是推荐摄入上限或处方。

## 数据修正与兼容

旧库熟牛肉的NDB号实际对应生牛肉，改用 FDC 171794（90%瘦牛肉末、熟、煎炒），230kcal/100g；这是参考食材，不能等同所有熟牛肉。硬豆腐改用FDC 172448；软豆腐FDC 172449单独保存。其余食材按匹配的原始条目同步。

启动时先完整校验数据，再导入。已存在的数据库在版本变化前使用SQLite backup生成一致备份，位置 `data/backups/`。个人表不改写；已保存计划与小食保留生成时的营养和来源快照，新生成、换批或添加才使用新资料。再次启动且数据未变化时不重复导入或备份。

不要用「重新生成」验证旧计划保留：重新生成本来就会替换当天安排。可以切换至未使用的日期测试新推荐；确认恢复原日期后游泳和小食仍然存在。

## 如何验证

1. 启动服务，刷新网页；「食品数据」显示64条与 food-catalog-v1.1-20261010。
2. 进入「饮品与小食」，搜索热奶铁，分别显示小、中、大规格及官方来源。
3. 选一份加入今日，检查首页已选小食、参考热量增量和刷新后的记录。
4. 旧日期的画像、计划和游泳仍然存在；生成调整草案并确认前，正式安排不变。
5. 选择一个新日期，在DeepSeek模式生成计划，检查来源、忌口与可执行性。真实API调用需使用本地Key，由用户主动触发；自动测试使用模拟回复。

## 验证与下一步

51项后台测试通过，覆盖原有功能及数据升级备份、个人记录不变、官方规格持久化、未知值保留、可疑记录隔离和忌口拦截。浏览器检查通过搜索、按规格添加饮品、首页能量增量、刷新后游泳与饮品保留、64条食品显示和390px手机无横向溢出。检查使用空临时数据库，不访问个人记录或调用付费模型。

已在实际项目完成导入，对升级前后的 profiles、plans、adjustments、events 全部记录逐表比对，内容保持一致；SQLite完整性检查及实际本地API检查通过。

本轮保留步行与游泳两种运动。下一阶段先测试三类用户：加班忙碌、喜欢奶茶咖啡、有明确忌口。记录生成成功、推荐是否能执行、替换能否满足需求、运动调整前后是否一致，再决定补充慢跑、骑行、瑜伽和力量训练。新增运动需记录强度、MET来源与适用范围，不应只添加名字与一个固定消耗值。
